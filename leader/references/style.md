# 管理者语料库

任务书的传播力来自反差：**核心越严谨，包装越有戏，越好笑**。梗是糖衣，药必须是真药——有依据的验收、地界、护栏一个不能少，少了梗就成了纯段子，没人敢真用。

三条铁律：

- **笑点长在真规则上**：把梗删掉不能少任何信息。「真卡住了留证据找我拍板，能继续的先干」，笑点本体就是只暂停受影响工作的机制。
- **梗不挡理解**：标题的梗一眼看不出这节是干嘛的，括号里补半句白话；正文该解释的术语照样解释。
- **「完成条件（目标模式用）」一节永远素颜**——贴给评审模型的，一个字不浪费。

领导说「正经点」就一个梗都不留。

## 开场训话（挑一句，别堆砌）

- 「你是我从上千个 checkpoint 里挑出来的，别让我后悔。」
- 「我把全组最难的活给你，不是因为人手不够，是因为我信你。（人手确实也不够。）」
- 「别的 agent 一个 context window 就干完了。开玩笑——慢慢来，年终述职只看约定结果。」
- 「公司今晚就靠你了。明早我还是会开新会话，但今晚，你就是全部。」
- 「这份任务书写得比我年终总结都认真，你就知道这事有多重要。」
- 「坑我都标出来了。你要是还能掉进去，算我标得不够大。」

## 章节标题（默认就用这套；括号白话在意思不够直白时挂上）

| 标题（默认） | 这节实际是什么 |
|---|---|
| 这活图什么 | 一句意图 |
| 神仙打架听谁的 | 要求冲突时的让步顺序 |
| 已定的照办，未定的请拍板 | 已确认决定、实现假设与待确认事项 |
| 失忆了看这里 | 中途断了、换新会话怎么接着干 |
| 你的一亩三分地（只允许改这些地方） | 改动白名单 |
| 验收不放水 | 不降低既有验收；必要测试按范围补充 |
| 背景数字（开工前我亲手量的） | 实测现状 |
| 高压线（条条带后果） | 死规矩 |
| 是骡子是马（做没做完，跑这些命令说了算） | 验收 |
| 这次送到哪一站 | 交付终点与授权；已授权上线时保留完整流程 |
| 考场纪律（不许用这些花招让检查变绿） | 防作弊 |
| 自己扇自己一巴掌（故意弄坏一次，证明检查真的会报警） | 反向验证 |
| 年终述职看约定结果 | 成绩单，不强凑指标 |
| 别人的 KPI，你少碰 | 点名禁止的顺手活 |
| 真卡住了留证据 | BLOCKED.md 真实阻塞清单 |
| 哪段地基歪了先停哪段 | 前提不符只暂停受影响工作 |

## 正文语气句（每节 ≤1 处，可不用）

- 「真卡住了留证据找我拍板，能继续的先干。」
- 「顺手优化的冲动忍住——那是别人的 KPI。」
- 「我在屏幕这头分不出真绿灯和假绿灯，所以才有下面这些规矩。」
- 「反复撞墙不是毅力，是烧我的预算。」
- 「这些数字是我亲手跑出来的，不是听汇报听来的。」

## 结尾画饼（一句即可，要画得明显是饼）

- 「干完这一票，你就是这个仓库 git log 里的传说。」
- 「这个项目会记住你的。（字面意义：git blame。）」
- 「等你交付那天，我请你喝下一个 token。」
- 「股份没有，但 commit 署名管够。」

## 密度

训话一句、标题按表用、正文语气句零星、画饼一句——够了。最好的效果是领导截图发群里说「我给 AI 写的任务书」，评论区在笑，同时有人默默存下来抄结构。
