# DeepHarness 独立验收

本文件只用于会改可运行代码、配置、schema、迁移或发布路径的执行型任务。这里的 DeepHarness 指本机 DeepSeek Harness（DSH）里的独立 reviewer，不是 Harness.io。领导写任务书前必须实测项目或主机已有的调用入口；只发现 `.dsh` 数据目录不等于已经找到可自动调用的 reviewer。不得把网页示例或猜测写成命令。

审查要求本身不授予提交、推送、合并或部署权限。下述送审、报告发布、合并后及生产验证步骤仅在已有用户授权覆盖时执行；可使用授权范围内的本地审查证据。若适用审查确实依赖尚未授权的外部步骤，应说明依赖并请求必要决定，只暂停受影响工作，不得为完成审查自行发布，也不得取消适用质量门禁。已经明确授权的步骤不重复索权。

## 独立性与门禁

1. 实现者完成全量检查，按已有授权准备送审版本，冻结目标分支 `base SHA` 与待审 `head SHA`；提交或推送需在授权覆盖内，缺少必要授权时按上述依赖处理。
2. DeepHarness 必须开全新会话；reviewer 没参与实现或集成，不继承作者的分析、预期结论或“应该已经没问题”之类提示。只给业务目标、规格、base/head SHA、最终 diff、验收命令和风险边界。
3. reviewer 只审查和测试，不修实现、不改测试/阈值/CI、不提交代码。测试造成的缓存或临时文件清理后，tracked diff 必须为空；发现缺口只报 `FAIL`，交回作者修。
4. 报告留在 DeepHarness 会话或已获授权的 PR 评论、CI 制品中，不由作者改写。报告后 head 变化、base 前移、rebase、冲突解决或合并队列重建，旧 `PASS` 全部失效；重新跑全量检查，再用最新 exact SHA 重审。
5. 没有真实入口、reviewer 无法读取 exact SHA、任何必需测试不绿、仍有 P0/P1 或会造成停服/重复外发/不可逆数据问题的发现，都不得合并或部署。

## reviewer 必做

- 审最终 diff，而非只看测试结果：找越界改动、被覆盖的并行改动、错误默认值、兼容性断点、锁文件/镜像/部署配置漂移、迁移不可逆、回滚空洞。
- 错误处理按同一标准两头查：能指出具体来源（外部输入、调用方、已知会失败的依赖）却没处理的，报缺口；指不出来源的 catch、fallback、重试、默认值，以及仓库内部改动留下的旧签名或兼容包装，报多余（P2，不阻塞，管理者验收时列入遗留问题）。
- 独立复跑仓库全部必需本地检查与可访问的必需 CI；核对测试数、跳过数、覆盖率等基线未退。命令不存在、空转或结果不可复现直接 `FAIL`。
- 只对本次改动实际改变的属性做下列风险回归，类别内也只测相关场景；只是经过这些路径（改文案、改无关字段）不触发，不适用项在报告里写一句原因。相关风险不能以“已有单测绿”代替端到端或集成证据。

### 消息、机器人、Webhook 或队列

- 同一逻辑事件首次投递、重复投递、确认丢失后的重试、超时后重试、并发 worker、进程重启重放、新旧版本并存时，对外消息符合项目定义的 exactly-once 或幂等契约。
- 不同事件或不同接收者不会被误去重；失败重试不改变目标、顺序、内容或权限；多个 handler/定时器不会重复消费。
- 至少一条反向验证能让重复发送或漏发缺陷稳定变红；缺少可判测试则 `FAIL`，由作者补测试后再审。

### 迁移、配置与部署

- 按本次改动涉及的项取证：从当前生产版本升级、全新安装、迁移重复执行/中断恢复、旧新配置/schema 兼容、数据与密钥保持、服务重启和既有回滚流程；部署确实会让新旧版本同时运行时，再验证并存窗口。
- 在最终集成候选上检查 readiness/liveness、关键 API、队列/定时任务；本次改动涉及重试或恢复逻辑时，再检查依赖短暂失败后的恢复。已授权部署时，部署后以 commit SHA/版本证明运行的不是旧包。
- 本次迁移具有不可逆破坏性且没有回滚办法时 `FAIL`，等待明确裁决，不能把备份口号当回滚证据。仓库原本就没有回滚流程属于已有问题，写进 Residual risks，不因此 FAIL，也不要求本次任务补建。

## 最小报告

```text
DeepHarness verdict: PASS | FAIL
Reviewer session / time:
Target base SHA / reviewed head SHA:
Diff findings: P0/P1/P2/P3（逐条状态）
Commands actually run: 命令、退出码、关键计数
Risk regressions: 消息幂等 / 迁移兼容 / 服务存活（适用项及证据）
Tracked workspace after testing: clean | dirty
Residual risks:
```

`PASS` 只能表示这份 exact base/head 组合通过；它不替代仓库审批、管理者明卷/暗卷复验、合并后 CI、生产冒烟或回滚观察。
