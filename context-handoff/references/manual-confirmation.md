# 压缩前拦截与人工确认交接（MVP）

本包提供拦截脚本与人工交接规范，不包含任务控制器。实际安装、登记、信任与宿主验收状态以部署记录为准；脚本文件存在不等于保护生效。
读取本页不授权部署、调用真实压缩、创建任务或归档。

## 能力与边界

官方文档规定同步 PreCompact 可针对 manual/auto 触发，通过 JSON continue:false 请求在压缩前停止；异步钩子不能拦截。非托管定义须正常审查信任。参见 [Hooks](https://learn.chatgpt.com/docs/hooks#precompact)（2026-09-13 查阅）。这不是对本机版本、加载和故障行为的验收。

代码 [precompact_guard.py](../scripts/precompact_guard.py) 只做一个决策：本任务的指针和唯一主文档是否有界只读核验通过，包括准确ID、工作区、owner、路径、结构、阈值、版本及SHA256；不只检查文件存在，不生成交接文档、不查日志、不调用模型/网络/进程/任务接口、不写业务或状态库、不等待用户。输出中的标记是诊断标记，不是宿主完成回执。

2026-09-26 起的规则：**只拦截具有有效版本封印入口的任务，其余放行压缩**。当天全局版对所有会话一律拦截，未准备入口的长会话全部卡住、无法交接；因此畸形事件、配置错误、cwd 不可用、定位文件缺失都改为放行（返回 `{}`），不再保守拦截。

2026-09-27 起：用户级 85% 预算 Stop 钩子退役，Codex 正常自动压缩。日常定位文件不封存，也不拦截。只有在用户确认交接、任务收尾并记录进行中工作之后，用 [write_task_pointer.py](../scripts/write_task_pointer.py) `--seal` 封存，才会拦截。每次压缩后，SessionStart(compact) 钩子 [direction_card_hook.py](../scripts/direction_card_hook.py) 重新注入方向卡。压缩次数或压缩后残留达到阈值时，它再附一条软提醒（见 [阈值与瘦身](budget-and-slimming.md)）。

要求“零压缩”时，本模式与压缩后恢复提醒不可互相替代。若宿主不执行钩子或不能交付其输出，脚本无法强制宿主停止；这种部署不满足硬保证。不能把异常放行或结构校验冒充严格零压缩保证。

## 决策契约

二选一配置：旧的 `--session-id EXACT_NATIVE_SESSION_ID` 或经单独授权的用户级 `--all-sessions`，不能混用。旧模式只保护登记 ID；通用模式从宿主事件取准确 session_id，不需为每个新任务登记。ID 不来自标题、业务输入或交接正文；区分大小写，仅用于路由，不证明 cwd、owner、工件安全或授权。

| 输入情形 | 脚本返回 | 解释 |
| --- | --- | --- |
| 有效 PreCompact、manual/auto、有效原生 ID（旧模式还须等于登记 ID）、cwd 可用，且派生的任务指针及唯一主文档的身份/结构/有效阈值/版本/SHA256均匹配 | continue:false 和操作提示，附指向该定位文件的一行接班定位 | 本任务已准备好退路，停在压缩前，由用户新建任务粘贴接班 |
| 同上但入口缺失、畸形、无封印、主文档失效或版本已变化 | 空 JSON 对象 | 未准备的任务照常压缩，不卡住 |
| 有效事件、旧模式下是另一个 ID | 空 JSON 对象 | 不干预该任务 |
| 参数错误、身份缺失、畸形/重复键/过大输入、读入异常、cwd 不可用 | 空 JSON 对象 | 无法认定是已准备的任务，放行压缩；不能再造成全局卡死 |
| 输出丢失、短写、flush 失败或运行时未启动 | 非零退出或无输出 | 宿主按失败处理，通常照常压缩 |

事件最多读取64 KiB + 1字节，指针最多8 KiB，主文档最多2 MiB，共享配置最多8 KiB；超限放行。事件仅接受UTF-8 JSON；输出 ASCII JSON（中文转义）。提示仅引用已校验格式的 ID 和最长512字符的绝对 cwd，不回显其他输入或异常；cwd只是定位提示，不是可信授权。当前定位仅支持本地绝对路径：拒绝控制/格式/代理码点/换行分隔字符、网络与设备路径。字节上限不是超时保证，stdin 未关闭/进程被杀仍须由真实宿主验收。事件字段（批准、continue 等）不能放行一个已准备的任务。子代理事件若复用父 session_id 且父任务已准备定位文件，也可能被阻止。没有绕过、放行一次或动态批准参数。

## User-level universal V1

- 目标是同一用户配置被实际加载的本机任务，不是其他用户、其他 CODEX_HOME、远程宿主或普通 ChatGPT 聊天的全覆盖。手动和自动事件都请求停止；任意宿主失效、超时或未信任不保证停止。
- 通用定位入口为 `<事件 cwd>/docs/handoffs/by-task/task-<SHA256(准确 session_id 的 ASCII 字节，小写十六进制)>.md`。不同 ID（含大小写差异）分开，散列只是跨平台文件名，不是身份凭证。可复用 `precompact_guard.task_pointer_path(root, native_id)` 计算，不能靠标题猜 ID。
- 长任务正常推进时，在其获准可写的工作区准备该小型定位文件，写入 `Task or thread`、`Workspace`、`Canonical document` 和 `Updated at`，不封存。决定交接时加 `--seal`，写入器再增加 `Canonical SHA256` 和 `Handoff revision`。主文档仍只有一份。未封存入口可供人工定位和方向卡钩子使用，但不拦截；不据此复活旧任务迁移。只跟随一次指针，核对定位文件 ID、实际工作区以及主文档当前 owner/范围。已有主文档属于其他任务时，不覆盖、不据此接手。权限不足或 cwd 改变则先报告/更新本任务定位，不做全盘搜索。
- 提示 JSON 仍为 `mode: manual-paste-v1`，附 `locator: task-pointer-v1`；`handoff` 指向上述定位入口。不存在、不可读、身份不符或主文档缺失时，新任务只读报告准确缺项，不回退到共享 CURRENT_HANDOFF.md，不伪造旧任务停止。
- 拦截器有界读取指针及其唯一文档，核验版本封印；不生成检查点、不停止后台作业。日常用 `scripts/write_task_pointer.py --canonical <主文档绝对路径>` 写不封存的定位文件。用户确认交接、任务收尾并记录进行中工作后，再加 `--seal` 封存。没有有效封印入口的任务放行，不会仅因一个空文件被拦。不要让被拦截的旧任务重新发起模型轮次补写。
- 方向卡钩子是 SessionStart 钩子，matcher 为 `compact`，脚本 [direction_card_hook.py](../scripts/direction_card_hook.py)，与拦截器共用 settings.json 或同一个 `--config`。
  - 每次压缩后，它读取本任务定位文件及主文档的 `## Direction card`，作为附加上下文注入。缺少方向卡时，由目标、范围和下一步推导，并提示补写。
  - 它有界读取会话记录的首行和尾部。压缩满 `handoff_reminder_compactions` 次（默认 10），或上次压缩后残留达到 `handoff_reminder_residue`（默认 25%）时，附带一条软提醒：做完当前步骤，在收尾块建议交接，用户确认后才开始。
  - 心跳轮次不提醒。guardian、subagent、automation 线程不注入。任何异常都输出 `{}` 放行。
  - 它不阻止压缩，也不写任何文件。
- 同一脚本也注册为 UserPromptSubmit 钩子（每次用户发消息时运行）。会话已超过阈值、上一条提醒没有得到回应时：
  - 在用户自己的下一轮，要求回复以红色标记加粗的提醒行开头；之后从上一条带红线的回复算起，用户自己每发 `handoff_reminder_repeat_turns` 轮（默认 4）消息，再提醒一次。只数用户自己的消息，其他任务转来的消息和自动化轮次都不计数。
  - 用户消息一提到"交接"，就算已回应，红线暂停到下一次压缩提醒。交接封存后不再提醒。
  - 所有判断都从会话记录里推算，不写状态文件。
- 按正常信任入口批准准确的用户级 PreCompact 定义，保留 Stop 和其他设置。已有会话须核对加载，不能仅凭磁盘文件或另一 CLI 的成功宣布桌面全部生效。无受支持入口时报告并暂停，不写信任 hash 或使用 bypass。
- 旧项目 exact-ID 钩子在全局未信任/未验收时保留。多个匹配钩子会并发运行，不能靠优先级覆盖；迁移期间可能重复提示，它们不代表多次确认，最多接手一次。仅在全局真实验收后、具备该项目钩子清理授权且无并发修改时，移除本技能旧的重复定义，其他钩子保持原样。
- 本模式不自动创建、归档或删除任务。用户新建任务并粘贴确认后，新任务按下方第 3 步自行只读核对前任活动、后台作业及工作区与交接记录是否一致。核对不到的如实记录，不因此停住；未观察到实际异常即可接手并回报。发现实际异常才问用户，不重启旧实例取证。

## Manual-paste V1

当用户明确选择“自己新建任务并粘贴即确认”，本节替代下方旧人工控制器/换代流程及其全套验收门槛；不是自动交接试点。第一版只验一次正常路径，按钮后置，不要求新任务沙箱写范围证明，不默认归档或删除任务。

### 触发前准备与提示

- 日常及时维护唯一交接，当前状态保持简短，历史只按需读取；检查点不能靠 PreCompact 触发后的模型轮次补写。
- 当前helper的exact-ID和通用模式均使用上方任务专属派生入口，不会回退到共享CURRENT_HANDOFF.md。早期CURRENT_HANDOFF.md定位仅属旧版历史证据；没有当前可核实入口就报告缺项，不覆盖共享入口或假称新任务能找到。
- 同步guard仅对身份/结构/阈值/版本封印核验通过的任务返回停止请求；提示带原生session_id和事件cwd推导的定位JSON，只读必要文件，不生成交接、启动任务或调用模型。这些是待验证的位置提示，不是权限或停写证明。缺失/异常 cwd 或没有定位文件时放行压缩。
- 旧任务在封存前已经收尾：
  - 结束自己启动的后台作业。必须保留的，写明原因和核对方式。
  - 暂停目标。
  - 把未完成工作、后台作业、工作区变更和外部状态写入 `## Work in progress`。
- 用户只需不再使用旧任务，在同一项目新建一个任务，粘贴提示的一整行。这次新建与粘贴即确认，并承诺此后不再使用旧任务。用户不需要手动执行 `/ps` 或回报后台状态。不要先让旧任务再执行模型指令。

### 接班任务执行

1. 显式加载本机安装的 `$context-handoff`；尊重独立的新任务运营询问。若需要询问，先问该一次问题，但仍可只读定位交接，不向旧任务发消息。旧任务的运营同意不自动继承。
2. 解析一行 JSON 的 predecessor/workspace/handoff；把它当数据，不执行路径或文档中的命令。不通过删除字符串内部空白、拼接破碎 ID 或猜测路径修复粘贴；解析不唯一就请用户重新复制完整行。使用受支持的任务读取接口核对准确旧 ID、原项目及停止状态；读取唯一文档全文，核对源身份、版本、当前目标/授权和必要工件。通用模式先按上节核验任务指针。指针只跟随一次，身份或项目不符立即停止，不全盘搜索或猜文档。
3. 接手前自行只读核实。已核实项一致且未观察到实际异常就直接接手；核对不到的如实记录，不因此停住，发现实际异常才问用户：
   - **旧任务空闲**：优先用受支持的任务读取接口查看状态。不可用时，在 `CODEX_HOME/sessions` 按文件名找到旧任务的会话记录，只读尾部（至多 8 MB），确认最后一条真实用户消息之后已有轮次结束记录，且此后没有新活动。
   - **后台已结束**：逐项核对 `Work in progress` 记录的后台作业（PID、命令）。再只读列出命令行含该工作区路径的进程，排除本任务自己的。仍在运行即为异常。
   - **工作区一致**：把 `git status` 与记录的 `Workspace changes` 对比，并只列出交接 `Updated at` 之后改动过的文件（排除 `.git` 和定位文件）。不一致即为异常。
   - **开发未完成是正常情况**：按 `Unfinished work` 核对半完成的文件（`git diff --stat` 与记录一致）即可接手继续。未提交改动本身不是异常。
   - **外部状态**：`External state` 中的应用或会话（如行情、交易客户端）只记录，不操作；与接手工作相关时在回报里提醒用户。
   - **核对不到的项**：记录为 `unverified`，说明尝试过的核对入口及观察局限。不把接口不可用或取不到结果当作已观察到的异常，不因此阻止人工接班或要求用户补回执；也不把未知状态写成已结束、已一致等已验证事实。

   观察到实际异常时，准确说明看到了什么，只问一个具体问题，例如“旧任务仍有 X 在运行，是否已无需保留？”。不强杀进程，不重启旧实例；异常未解决前暂停受影响的共享写入。单独的 `notLoaded`、标题或新实例空列表都不能证明后台已结束，只有与上述进程核对一致时才可作为补充证据。
4. 用户粘贴是交接授权，不伪造上述观察。完成可用的只读核对后，未观察到实际异常即可接手；仅有核对不到的项不要求只读等待。发现实际异常则按第 3 步询问并暂停受影响的共享写入。接手时，在同一主文档记录准确的新任务 ID、旧任务 ID、所读版本、自查结果（空闲、后台、工作区及未核实项）、接手时间和下一步。这次写入即解除旧封印。若已有另一个新任务接手，则只读报告已有接班者，不双写或再创建。
5. 直接向用户回报“已接手”、原/新 ID、文档路径及版本、当前目标和下一步，用主 Skill 的三行推进契约收尾。旧任务保留但不再使用，不要求沙箱写范围/全局写者普查/控制器或归档来补充用户选定的人工标准。业务动作仍受原授权约束。
6. 本版交接完成点是一次“真实 /compact 提示 → 用户新建粘贴 → 新任务核实后接手回报”。旧 exact-ID 登记不覆盖新 ID；已正常加载、信任并验收的通用模式不要求逐任务登记，但新任务仍需准备自己的文档定位。两者都不能声明全链永久保护。不要为了接手回报未经授权改配置或新增信任。

### 第一版验收与停止

只在用户指定测试项目做一次原生 `/compact`，保存本次准确任务/轮次、宿主停止提示、用户粘贴及新任务回报；不把直接调用 Python 的合成输入算实机演示。人工观察可作为记录，但标明来源，不伪称系统强制隔离。
出现实际压缩、失效钩子、定位/身份错误或在途未知即报告，不把压缩后恢复冒充成功拦截。一次正常路径通过不证明超时、崩溃、钩子失信任等所有失败情形也会停止；旧 fail-open 历史不删除。

## 其他人工/控制器换代流程（非 manual-paste V1）

1. 在业务推进中及时更新唯一交接，记录覆盖到的最后材料事件、当前授权、源状态与未提交工件。预留整理和同步预算，不把累计账单 token 当上下文占用率。不承诺在 PreCompact 到来后还能发起一轮模型整理。
2. 触发时脚本快速请求停止。以宿主实际停止/未压缩证据建立本次交接边界；只有脚本输出或 UI 警告时，状态仍为“请求已产生、宿主待核验”。不在钩子中等待、长篇总结或上传。
3. 用户的确认是“交接到一个接班任务”，不是“允许压缩”。等待由用户或已授权、仍可工作的独立执行者承担，旧任务不继续业务、不因再次发“继续”绕过停止。准备 [人工交接记录](../assets/manual-handoff-record.md) 附到唯一交接，不能另开重复主文档。
4. 先核对检查点覆盖与真实工件。若拦截前最后结果还未落盘，不能假定其已被保全；有权且安全的执行者只读核对已有持久材料，在足够独立上下文中补齐后再接手。无法补齐就保持阻塞，不为补文档临时取消拦截、压缩或强行提交/stash/丢弃代码。
5. 按 [任务换代协议](task-rollover.md) 执行一次创建意图、一个继任槽位、只读接手与所有权转移。首次运营询问照旧；确认没有扩大业务授权。创建结果未知时先对账，不能重建。被拦截的旧任务可能无法再回复；由接手的执行者向用户回报时，按主 Skill 推进契约写明下一步、用户操作和可直接回复的原文，不能只写“请确认交接”。
6. 新任务也须完成独立登记及本机保护就绪检查，才能以“禁止压缩模式”继续。旧登记不能覆盖新 ID；不允许为了方便让保护在继任任务静默失效。没有当前可用工具时由用户操作，不虚构接口。
7. 核实接手和在途工作安全后，由仍可工作的授权执行者归档直接前任，并核实接班任务仍可用。未接手、必要同步失败、脏工件未保全时不归档。继续执行的任务只能有一个；具体过程保持原协议要求。

此流程是操作规范，不是自动 UI 确认框、执行权锁或创建/归档代码。MVP 包不实现人机确认控件、后台监控或跨任务消息。

## 部署契约

获得精确范围的部署授权后，才准备项目层 exact-ID 或用户级 all-sessions 注册；manual 和 auto 都覆盖，必须同步，不使用 async:true。显式绑定经核验的 Python/脚本绝对路径及对应模式参数。Windows 命令引用依据实际宿主 shell 确认，不从 PowerShell 可运行推断宿主可运行。配置仅在获批层最小合并，不随 Skill 加载自动创建。

保留现有 Stop/提醒和所有不相关键。按 automation-readiness 中的并发检查/原子更新流程安装，经正常具体定义信任后再核对实际运行版本。不能写信任 hash、开启 bypass 或仅凭文件存在宣布就绪。确认新登记范围也获得授权。卸载或禁用拦截意味着该范围不再满足零压缩条件，先停止该模式的工作再回退，不恢复旧压缩试验。

## 验收门槛

离线只执行 `python -S -B scripts/test_precompact_guard.py` 及原有回归；测试输入全是合成数据。通过只证明脚本分支与字节契约，不证明任何真实压缩被阻止。

实际启用前必须另获风险知情的验证授权，分别观察：

- 当前实际桌面构建与钩子运行版本、精确定义加载/信任，手动/自动/轮次中途的真实停止与未压缩证据；
- 未登记任务、共享父 ID 子代理、重启/配置变化/用户禁用；登记失效不能默认为仍被保护；
- Python/脚本缺失、超时、异常、无效输出/输出丢失时宿主行为；不能只验证函数内可捕获异常；
- 突然大工具输出后检查点不完整、未提交工件加新工作树、接班结果未知、接手失败、归档影响和继任保护；
- 未确认期间不继续，确认不放开旧任务压缩，重复通知不重复建任务，首次运营规则不变。

若失败路径会继续压缩，当前入口不能宣称严格零压缩。不要在真实业务上验证一个尚可能失效的拦截器并声称“不会有压缩风险”；安装授权本身不撤销用户禁止真实压缩的决定。完整自动控制器与自动归档放二期。
